# Algobooth

A desktop DJ booth built around [Strudel](https://strudel.cc), the browser live-coding music environment.

- **Booth.** Two Strudel decks, a crossfader, sync, and a few knobs. Runs offline.
- **Library.** Your patterns, ripped or written, in a tree you organise yourself. Plain JSON files on disk.
- **Rip.** Give it a YouTube link and a start and stop time. It separates the stems, works out tempo, drums, bass and chords, and hands back Strudel code you can tweak.

## Run

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # Rust toolchain
pnpm i
pnpm tauri dev   # fetches the bundled sound packs first when they are missing
```

## Test

```sh
pnpm test
cd src-tauri && cargo test
cd service && uv run pytest
```

After a Strudel version bump, run `pnpm build-methods` to rebuild the Methods catalogue; until you do, `app/src/methods/catalogue.test.ts` fails because the installed version differs from the catalogue's.

## Sounds

Everything plays offline from `app/public/samples`, which `pnpm fetch-samples` fills once (and `pnpm dev` / `pnpm build` run it first; `pnpm fetch-samples piano soundfonts` fetches only the packs named). The packs are listed in `app/src/engine/packs.ts`:

- **Drum machines.** The 909, 808, 707, 606, 505, LinnDrum, MPC60, SP-12 and DR-110 (`.bank("RolandTR909")` or `.bank("tr909")`). A drum name with no bank plays the 808.
- **Piano.** `s("piano")`, the Salamander grand strudel.cc plays.
- **General MIDI instruments.** 37 `gm_*` soundfonts: Rhodes and DX pianos (`gm_epiano1`, `gm_epiano2`), organs, basses, strings, choirs, brass and the synth pads (`gm_pad_warm`, `gm_pad_poly`, `gm_pad_halo`, ...), up to three fonts each (`.n(1)` picks the second). The fetch converts each webaudiofont preset to plain MP3s and a JSON zone map, so the app never evaluates downloaded code.
- **Dirt-Samples.** The workshop's sounds plus the house ones: `stab`, `juno`, `jvbass`, `bass1`, `bass3`, `moog`, `pad`, `padlong`, `rave`, `hoover`, `realclaps`, `clubkick`, `linnhats`, `sax`, `pluck`, `arpy`, `yeah`, `breaks125` and more.
- **Synths.** `sine`, `square`, `triangle`, `sawtooth`, and `supersaw` with `.unison()`, `.detune()` and `.spread()`; `.fm()`, the filter envelopes (`.lpenv()`), `.shape()` and `.distort()` make them sound like more than a chip.

**Lanes and sidechain.** Inside a deck, Strudel's `.orbit(n)` picks one of the deck's own eight lanes, and `.duckorbit(n)` on a kick ducks that lane: the strudel.cc sidechain idiom, so `.orbit(2)` on the bass and pads and `.duckorbit(2).duckattack(0.2).duckdepth(0.7)` on the kick makes them pump. Deck A's lanes and deck B's never mix (deck A's lane 2 is superdough orbit 12, deck B's is 22), and every lane goes through its deck's knobs, fader and the crossfader.

**Master.** The summed mix runs through the master filters, a **glue** compressor (the master fader of that name: off at the bottom, about 1.7:1 from -6 dB by default, 3:1 from -18 dB at the top), the master volume, a limiter at -1 dB and a soft clipper, so two hot decks never clip the output. The deck and master reverbs are a stereo hall that darkens as it decays.

## Library

Patterns live in `~/Algobooth/library` as plain JSON files (change the folder in Settings). A brand-new library is seeded with the examples in `library-example/`: three single parts in `mine/`, and in `house/` four full tracks (deep house, piano house, French filter house, Chicago jack) and a few parts (Rhodes chords, a sub bass, strings and choir, a sidechain kick). An existing library is never written to; copy the folder in to get them (`cp -R library-example/house ~/Algobooth/library/`). `app/src/library/examples.test.ts` checks every example evaluates, keeps its tempo, plays only shipped sounds and sounds in every bar of every line. Rest the pointer on a pattern to see its code. Drag it onto a deck's body to load it, or onto a deck's header to cue it (see Keys). Double-click sends it to the target deck, the one you last clicked, typed in or loaded, marked "◂ library" in its header: a stopped deck **loads** the pattern and a playing deck **cues** it. Shift+double-click does the other one, and right-click offers Load to A / B and Cue on A / B.

## Methods

The Methods panel on the Booth's right edge lists Strudel's chainable methods (`.lpf`, `.room`, `.fast` and about 270 more) in folders: Sound, Pitch, Filter, Envelope, Dynamics, Ducking, Delay and Reverb, Modulation, Distortion, Pan and Space, Time, Structure and Other. Below them a Functions section lists the standalone functions (`seq`, `stack`, `cat`, the signals such as `sine`, the random pickers, `run`, `setcpm`) in folders Combine, Signals, Random, Sources, Setup and Other. The folders start collapsed; the search box looks across all of them. Rest the pointer on a row, or focus it with the keyboard, to see the call as it will be inserted, Strudel's own description, synonyms and parameters. Drag a row onto a deck's editor and `.name(default)` lands at the end of the line you dropped on, whatever column, with the default argument selected so you can type over it. Double-click inserts on the cursor's line of the target deck, marked "◂ library" in its header. A drop on a blank or comment line borrows the nearest pattern line, and a bare label such as `$:` sends it to the pattern body below; a line that opens a bracket like `stack(`, or a document with no pattern line, shows "drop onto a pattern line" under the deck. A function is an expression rather than a method call, so it lands exactly where the pointer is, as a complete expression such as `sine.range(0.2, 1).slow(4)` or `stack(s("bd*4"), s("hh*8"))`. The pointer must be where a value can go: inside `( )`, after a comma or a label, and anywhere else (inside a word, after a `)`, before a `.`) refuses with a message under the deck. On a blank line a combinator or source is written as its own `$:` line so the deck plays it, `setcpm` goes in as it is, and a signal refuses because it has nothing to drive. Nothing plays until you press Update. A deck's Format button lays every chain out one method per line (`bass: note("g1")` then `.s("sawtooth")`, `.lpf(370)` indented under it, a chain inside an argument staying inline); it is one undo step and changes nothing the deck plays.

The list is built offline from the JSDoc of the pinned Strudel packages (`pnpm build-methods` writes `app/src/methods/catalogue.json`), so the panel needs no network. Default arguments, the methods and functions left out and the tooltip notes are hand-kept in `app/src/methods/defaults.ts`; `samples(...)` is left out because it fetches from a URL. `orbit` and `duckorbit` take the deck's own lane numbers (see Sounds).

## Lessons

The Lessons tab beside Methods on the Booth's right edge is the Strudel workshop (first sounds, first notes, first effects, pattern effects and a recap), adapted from strudel.cc under its AGPL-3.0 licence. Each example has a ▶ button that loads it onto the performing deck (marked "◂ library") and plays it; change it there and press Ctrl+Enter. A deck holding a lesson example is named `lesson: …`, and the next ▶ replaces it without asking; any other unsaved code asks first, as a library load does. The workshop's piano, Dirt-Samples and General MIDI instruments all ship (only its `perc` plays the drum machines' `rim`), and a drum name with no `.bank()` plays the 808 (the 909 for the ride), as strudel.cc plays one. After a change to the workshop upstream, run `pnpm build-lessons <strudel checkout>/website/src/pages/workshop` to rebuild `app/src/lessons/workshop.json` (the committed one predates the bundled packs and still plays the old stand-ins, `triangle` for the piano and so on, until it is rebuilt); `app/src/lessons/evaluate.test.ts` checks every example evaluates and plays only shipped sounds.

## Keys

A key strip under each deck turns the computer keyboard into pads. Drag a method from the Methods panel onto a key to bind it (functions are refused: they go in the editor); drop a second method on the same key and it becomes a macro, one key for a chain. Press **Esc** to enter perform mode: the editor locks and the letters are pads, and Esc again gives the keys back to the editor. The performing deck is the one marked "◂ library" in its header; **Tab** switches it. The digits **1** to **9** pick the target line among the deck's pattern lines, which the editor gutter numbers in place of line numbers. A letter key taps or holds: a tap commits (the method is appended to the target line, or taken off if it is already there), a hold auditions it and reverts on release. **Shift**+letter nudges the bound method's argument up by a factor of 2 and **Ctrl**+letter down. The bottom row, Z to M, holds the pattern's named lines in document order (a rip's `_fills` and `_bass2` land on keys by themselves), and a press flips that line's leading underscore. **F1** to **F8** recall snapshots of the deck's code and **Shift**+F saves one. By default every change lands on the next bar; Settings → Keys chooses now, beat or bar, and the deck header counts down while something is queued.

**Cue.** A cue mixes a second pattern into a playing deck without stopping it. Cue one from the library (see above) and the deck's code gets a `// cued: <name> · <cpm> cpm …` comment followed by that pattern's lines, muted and prefixed with a short name taken from the pattern (`_acid_line:`, `_solomun_live_bass:`); its `setcpm` line is left out, so the deck keeps its tempo. Nothing new sounds yet. The cued lines sit on the free home-row keys A to L, in a blue tone, labelled without the prefix, and a press flips one on the bar like any line key. The deck's header shows `next: <name>` with **Go** and **Clear** buttons (in perform mode, **Enter** is Go and **Shift+Enter** is Clear). Go lands on the bar: the deck's own lines go, the prefixes come off (a line still muted stays muted, and a numbered or bare-slug line such as `_acid_line_1` still muted keeps its prefix), the tempo stays, and the deck becomes the cued pattern, so it shows as changed from its file: Save then writes the mix over the cued pattern's file, Save as keeps that file as it was. Clear removes the cued block and leaves the deck's text exactly as it was, on the bar when a cued line is sounding and at once otherwise. A half-mix you saved comes back as a half-mix, with `(from file)` beside the cue, and Go then keeps the deck's own name and file. A deck can only be cued into when each of its lines is labelled (`$:` or `name:`): Strudel plays a bare last expression only while nothing is labelled, so the first cued pad would silence it, and the cue is refused with that reason. Design: [docs/superpowers/specs/2026-10-23-cue-lines-design.md](docs/superpowers/specs/2026-10-23-cue-lines-design.md).

On a Mac, F1–F8 reach the app only with “Use F1, F2, etc. keys as standard function keys” on in System Settings → Keyboard, or with Fn held.

Right-click a key for clear, hide for this pattern, keep with this pattern or make global. Method keys live in a global layout (Settings has Reset key layout); a pattern's own keys and snapshots are saved in its file under `keys`, so Save keeps them. The design is in [`docs/superpowers/specs/2026-10-22-method-keyboard-design.md`](docs/superpowers/specs/2026-10-22-method-keyboard-design.md).

## Fills

The **Fills** tab beside Methods holds ready-made drum fills: a two-bar snare roll build-up, a four-bar long build, a kick build, clap, tom and hat fills, a noise riser, half time, a drop-out and a crash. Click **inject** to play one over the track, or **switch** to mute the deck's drum lines (any labelled line whose `s()` names a drum) while it plays; the mode a fill suits best is in orange. It goes onto the performing deck at the next bar line, whatever the key quantise says, as a `fill:` line under a `// fill: …` comment at the end of the code, and comes out on its own after its bars, restoring the lines it muted, so the code ends as it was. A fill longer than a bar gets `.late(n)` so it always starts from its first bar. A new fill replaces one that is playing; Stop takes it out at once; a stopped deck refuses one. Drag either button onto a key to play the fill from the keyboard in perform mode: a tap plays it once, and a key still held when the fill ends keeps it looping until the bar after you let go. Snapshots are saved without the fill. The catalogue is `app/src/booth/keys/fills.ts`.

## Rip

The Rip tab sends a YouTube link and a start and end time to a local Python service (`service/`, package `algorip`), which downloads the clip, separates it into stems with Demucs, works out tempo, key, drums, bass and chords, and writes Strudel code for it: one named line per part (`drums:` for the kick, `claps:` or `snare:`, `hats:`, `ghosts:` for quiet hat ticks, `bass:`, `chords:`, `melody:`; the drum lines are loops, like the bass, each on the bank sample shaped like the stem's (`bd:3`) at the stem's level (`.gain()`), plus muted lines: `_bass2:` for what some bars add on top of the bass loop, `_fills:` for the fills: bars where the drum loops miss at least three hits, each in its own bar, and any drum voice that has no steady loop, and `_triads:` for the chords as heard), so you can mute one by writing `_bass:` in front of it. The app starts and stops the service itself.

It needs [uv](https://docs.astral.sh/uv/) on the path; `pnpm tauri dev` syncs `service/.venv` itself
(`uv sync`, a tenth of a second once it is there), so a fresh clone or worktree needs no separate step.

- **First rip downloads the models.** PyTorch, torchaudio, Demucs and the htdemucs weights are not part of `uv sync`; the Rip tab offers a one-time download of about 600 MB (561 MB on disk, measured). They go in the app data folder, `~/Library/Application Support/io.klimovski.algobooth/models` on macOS, and nothing else needs the network after that except fetching new clips.
- **Cache.** Downloads, stems and analysis results live in `~/Algobooth/cache` (change the folder in Settings). Ripping the same clip again is served from the cache, offline: the **Recent** menu on the Rip tab lists the cached clips; picking one fills in the link and window and brings back its last result at once (every rip stores its result beside its stems), and Analyse recomputes it. Source audio is deleted after a rip unless you tick "Keep downloaded audio" in Settings.
- **Bass is the loop.** The `bass:` line is the pattern the bass stem plays, not a bar-by-bar transcript: the analysis tests which period (1, 2, 4 or 8 bars) the bars repeat at. A bar belongs to the loop when it plays what the loop plays, whatever else it adds, so a sparse line with a varying last beat is still one bar; the loop's notes are taken from the bars that add the least, so a long build cannot outvote a short loop; and a longer period wins only when it explains clearly more of the notes, so an alternation is a two-bar loop but a varying beat is not. When no period fits, the bass is written out bar by bar. A beat of retriggered 16ths on one pitch is written `g1*4`.
- **Pitch.** Each 16th's pitch comes from a pitch tracker (pyin). A loud step the tracker is unsure of gets a second opinion from the spectrum, which corrects the tracker's habit of reading a note an octave down (the 48:50 Solomun clip's fourth beat); a quiet step never does, so tails and bleed stay rests.
- **Tuning and chromatic notes.** The clip's offset from 440 tuning (the median over the pitched steps) is removed before any note is rounded, and a note that is then clearly on a semitone keeps it even when it is not in the key; only an ambiguous reading, more than 35 cents from any semitone, snaps to the key. The 48:50 Solomun clip's third beat is an E3 in D# minor. An offset of 10 cents or more shows on the Rip tab's analysis line.
- **Filter.** The lowpass cutoff is the stem's own: the 85% rolloff of the notes' held part, and when the notes open at least an octave brighter at their attack and take 50 ms or more to close, `.lpenv().lpdecay().lpsustain(0)` move the filter the same way.
- **Gate.** When the stem's notes die before their end (6 dB or more down), the bass lines carry a measured envelope, `.attack(a).clip(c).release(r)`: the attack and the cut as the stem plays them, and the note held at full level for the share of its length the stem holds it. A held bass gets none.
- **Sound.** The bass keeps the oscillator its harmonics measure (`sawtooth`, `triangle` or `sine`) with the measured filter and gate, plus `.shape(0.3)` after the filter so it carries on small speakers; a sine bass also gets `.fm(1.5).fmdecay(0.1)`, an FM pluck on the attack only. The chords and the melody come from the same stem and share its instrument, chosen by how that stem sounds: a part that holds within 3 dB 250 ms after its notes start is a pad, `supersaw` with `.unison(5).detune(0.2)` and a lowpass at the stem's brightness; a part that falls is keys, `piano` when bright (rolloff 2.5 kHz or more) and the Rhodes (`gm_epiano1`) when mellow or when there is nothing to measure. The chords line is one chord per bar: the root and third the stem plays (the key's third when it plays none), a 7th or 9th when the stem plays one, and otherwise the key's own 7th for house colour (`Gm7` in G minor), in spellings the voicing dictionary knows (`m7`, `^7`, `9`, `m9`, `add9`). When the colour changes anything, a muted `_triads:` line right under `chords:` holds the chords as heard, on the same instrument: unmute it and mute `chords:` to compare.
- **Sidechain.** When there is a kick and a bass or chords line, the kick ducks the deck's lane 2 (`.duckorbit(2).duckattack(0.15).duckdepth(0.6)`) and the bass and chords play on it (`.orbit(2)`), the pump of the house examples; the lanes are the deck's own, so a ripped pattern ducks only its own deck.
- **Levels.** Every line carries its gain, in the ranges of the house examples: the kick at 0.65 and the other drum voices at their level against it on the stem (without one, claps or snare 0.5, hats 0.35, ghosts 0.15); the bass 0.5 to 0.55, Rhodes chords 0.6, piano 0.55, a supersaw pad 0.2. `app/src/rip/golden.test.ts` evaluates every golden's lines under Strudel and checks each plays only shipped sounds, and each unmuted line plays in every bar (a chord as at least three notes).
- **Variation.** What the bars add on top of the loop comes as a muted `_bass2:` line under the bass, with a comment naming the bars it came from: written once when those bars all add the same thing, and bar by bar when they fill in gradually. A bar adding fewer than two steps adds a stray, which is left out. Remove the underscore to switch it on.
- **Match.** The analysis line on the Rip tab ends with the loop length and a 0–1 match of the loop against the bass stem, for example `bass loop 1 bar · match 0.80`. The generated line for that clip is `bass: note("[~ ~ g1@2] [~ g1 ~ g1] [~ ~ g1@2] [~ g1@2 g2]")`.
- **Drum match.** The drum number on the analysis line, for example `drums loop 1 bar · 92% of hits`, is how well the loops' hits agree with the classified drum hits (an F1 score shown as a percentage), so a hit the loops miss and a hit they play that a bar did not have both lower it. It is agreement with the drum classifier, not with the stem, so read it as weaker than the bass match. Hits outside the loops go to the muted `_fills:` line when a bar has three or more of them; a voice with no steady loop is written there whole. Remove the underscore to hear them. The grid itself sits on the kicks: when the beat tracker lands half a beat off them, the beats are moved onto the kicks and the bar starts so the claps fall on 2 and 4.
- **Backtest a clip.** `service/scripts/bass_fixture.py` runs the bass analysis on a rip's cached stems and writes the expected loop as test fixtures; see `service/README.md`.
- **Optional tidy pass.** Put a Claude API key in Settings and tick Tidy on the Rip tab to have Claude rewrite the generated code more idiomatically, keeping the tempo. Without a key the pass is off and nothing leaves your machine but the YouTube download.
- **Limits.** A clip is at most 60 seconds. Demucs runs on the GPU through Metal, so ripping is supported on Apple Silicon Macs only.

See [`service/README.md`](service/README.md) for the service's API, and [the design document](docs/superpowers/specs/2026-10-19-algobooth-design.md) for how it works.
