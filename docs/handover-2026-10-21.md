# Algobooth handover, 2026-10-21

For a fresh session picking up where the last ones left off. Everything here is on `main` and pushed
(GitHub `TomKlimovski/algobooth`). Read this, then `README.md` and `service/README.md`.

## What it is

A native, offline DJ booth around Strudel for Tom's goal of playing a club set live-coding. Two Strudel
decks with a crossfader and master section, a library of patterns as JSON files on disk, and a Rip tab
that turns a YouTube clip into Strudel code that *emulates* it (Tom then tweaks). Tauri 2 shell (Rust),
Solid + Vite front end, a Python service (`service/`, package `algorip`) for the rip pipeline.

Run it: `pnpm tauri dev` from the repo root (the app starts and stops the Python service itself). A code
change on the service side needs a full relaunch, not Cmd+R, since the service is a separate process.

## Tom's principles (keep these)

- **Emulate, then tweak.** The rip's job is a short, readable approximation Tom can play with, never a
  wall of numbers.
- **As modular as possible.** One named line per part (`drums:`, `hats:`, `bass:`, `chords:`,
  `melody:`), the simplest loop on each line, and anything that varies as its own *muted* line
  (`_bass2:` for a build, `_fills:` for drum fills) with a comment naming the bars. Never fold a
  variation into a loop to be "more faithful". A leading underscore mutes a Strudel named pattern.
- **Never `.orbit()` in generated code.** Orbits are the app's deck channels (1 = deck A, 2 = deck B,
  3 = the rip result).
- No internet needed after the one-time model download except to fetch new clips; nothing leaves the
  machine unless a Claude API key is set and Tidy is ticked.

## State of the work

Milestones 1 to 5 of the original design are built (booth, mixer, master, sync, library, settings, rip
pipeline). Since then, three rounds on the rip's output, all merged:

1. **Named lines** instead of `$:` (2026-10-20).
2. **Bass loop** (`docs/superpowers/specs/2026-10-20-bass-loop-design.md`, plan beside it): Basic Pitch
   is no longer used for bass. `bassgrid.py` tracks pitch and onsets per 16th step with pyin;
   `loop.py` finds the period the bars repeat at with a two-pass majority vote (core bars vs deviating
   bars); `bass.py` runs a small candidate search (16th vs 8th grid, retriggered vs sustained) and
   picks the shortest notation within 0.05 of the best match; `score.py` scores against the grid with a
   frame pitch agreement and mir_eval onset F1. The build material of deviating bars becomes a muted
   `_bass2:` line, measured on sounding steps. `Analysis.bass_loop` carries it; the Rip tab shows
   `bass loop 1 bar · match 0.80`.
3. **Drum loop** (`docs/superpowers/specs/2026-10-21-drum-loop-design.md`): `drumloop.py` runs the
   same loop finder per drum voice; every hit the loop does not play, from every bar, goes into one
   muted `_fills:` line. `Analysis.drum_summary` feeds `drums loop 1 bar · 86% of hits` on the tab.
   Melody still uses the older strict `mini.consensus`; unifying it is open.

Other recent additions: the Rip tab's **Recent** menu (cached clips; picking one replays the stored
result instantly, Analyse recomputes), library **hover preview** of a pattern's code, library
**double-click target** = the deck last clicked, typed in or loaded (marker "◂ library" in its header).
The **Methods panel** (Strudel's chainable methods, drag or double-click onto a deck) is described in
`docs/superpowers/specs/2026-10-21-method-panel-design.md`.

Suites at head: `cd service && uv run pytest -q` (240), `pnpm exec vitest run` (166), `pnpm exec tsc
--noEmit -p .` clean, `cargo test` in `src-tauri` (42, unchanged for a while).

## The reference clip

Solomun, Live at Alexandra Palace, `https://www.youtube.com/watch?v=S46Bs4pZ_I4`, 36:40 to 37:00,
129 bpm, G minor, 9 bars. Its stems are cached at `~/Algobooth/cache/stems/6d44d581d8ad286f/` (never
commit audio). It is a committed golden: `service/tests/golden/solomun.*` (analysis, bass grid, strudel,
bass events). The bass is a one-bar G1 loop in bars 1 to 4 with a build in bars 5 to 9; today's output:

```
drums: s("bd*4, [cp ~ cp ~] [cp ~ cp ~] [~ ~ cp ~] [~ ~ cp ~]").bank("tr909")
hats: s("[~ oh ~ ~] [~ ~ ~ oh] [~ oh ~ ~] [~ ~ ~ oh]").bank("tr909")
// bars 1–9 add these hits (a fill): remove the underscore to hear them
_fills: ...
bass: note("[~ ~ g1@2] [~ g1 ~ g1] [~ ~ g1@2] [~ g1@2 g2]").s("sawtooth").lpf(800)
// bars 5–9 add this under the bass (a build): remove the underscore to hear it (match 0.80 without, 0.80 with)
_bass2: note("[g1 g1 ~ ~] [g1 ~ ~ ~] [g1 ~ ~ ~] [g1 ~ ~ ~]").s("sawtooth").lpf(800).gain(0.6)
```

`service/scripts/bass_fixture.py` builds the golden files for any cached clip's stems; that is the
backtest entry point for the next real clip.

## Open questions for Tom (by ear)

- Bass: the `g1@2` notes are written held; the first spike guessed retriggered 16ths. The stem's
  envelope shows no dip at those step edges, so held won. If Tom hears two hits, the retrigger rule in
  `bassgrid.py` is the place.
- Hats: the open hats had no clean period, so the one-bar majority vote made the four-hat line above.
  The alternative is no `hats:` line with every open hat in `_fills:`.
- `_fills:` on Solomun is long (claps vary in 8 of 9 bars). A threshold for "a bar differs enough to be
  a fill" is an option if it is too much to read.

## Gotchas

- **vitest 5 module cache.** `node_modules/.vitest-cache` keeps transformed test modules per file; after
  goldens are added or changed, run `pnpm exec vitest run --clearCache` or the golden glob test fails
  (its message says so).
- **Strudel bumps.** Re-run `pnpm build-methods` when Strudel is bumped, or `app/src/methods/catalogue.test.ts`
  fails (its message says so).
- **WebKit.** `fetch` and `setTimeout` must be called unbound (see `ripApi.ts`); vertical range inputs
  use `writing-mode: vertical-lr`; engine singletons force a full reload on HMR
  (`import.meta.hot.invalidate()`); the AudioContext is closed on `pagehide`.
- **Repl globals.** Concurrent Strudel evaluations mix `setcpm`/`hush` globals, so every evaluation goes
  through the eval lock (`app/src/engine/evalLock.ts`). The rip result editor takes edits only from
  document changes, never from the repl's state echoes (`ResultEditor.tsx` explains why).
- **Service token.** The Rust supervisor passes a random bearer token in the environment; `GET /health`
  is the only unauthenticated route. The port comes from the service's first stdout line.
- **Commits.** Trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`, nothing else.
  Subagents must be told explicitly or they write an Opus trailer. Plans are executed with the
  superpowers subagent-driven-development skill in a worktree session; those sessions tend to end their
  turn while waiting on an implementer and need a nudge ("do not end your turn to wait").
- **Process.** Design docs in `docs/superpowers/specs/`, plans in `docs/superpowers/plans/`; a fresh
  builder subagent reads each design before Tom sees it; Tom approves the design, then the plan, then
  the branch is merged into `main` by fast-forward after both suites pass locally.
