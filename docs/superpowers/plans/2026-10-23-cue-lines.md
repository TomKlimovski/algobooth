# Cue Lines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cue a second library pattern into a playing deck as muted, prefixed named lines under a marker comment, each on a home-row key, with Go to finish the mix and Clear to drop it.

**Architecture:** A new pure module `app/src/booth/keys/cue.ts` turns a pattern into a cue block, recognises a cue in a deck's code, and rewrites the code for Go and Clear. `effectiveLayout` places the cued labels on the home row. `KeyController` gains `cue`, `go` and `clearCue`, running through the existing per-deck queue (as a snapshot recall does) where the sound changes and at once where it does not. The Deck shows the cue in its header; the library store decides between load and cue on a double-click.

**Tech Stack:** Solid + TypeScript, vitest (jsdom for components), CodeMirror transactions through `DeckApi.applyEdits`.

**Spec:** `docs/superpowers/specs/2026-10-23-cue-lines-design.md`

## Global Constraints

- Commit trailer is exactly `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and nothing else. Commit messages are one sentence in the repo's style ("A deck's Format button lays every chain out one method per line").
- No `.orbit()` is ever written by the app; the cue copies the pattern's code as it is.
- The marker's first words are exactly `// cued: `; the hint and header copy are as the spec gives them.
- Muted means a leading underscore on the label; `$:` lines have no label and no key.
- `pnpm exec vitest run` (660 at head) and `pnpm exec tsc --noEmit -p .` must stay green after every task.
- Everything stays in `app/`; no Rust, no file-format change.

## Review Focus

1. A pattern name with ` · ` in it (the rip's names are `Title 36:40`, but a hand-named `A · B` is possible): `cueOf` must still read the name and cpm back from the marker. Test in Task 1.
2. A pattern whose name slugs to nothing (`"…"` or `"🎛"`): the slug falls back to `cued` and the block still has valid labels. Test in Task 1.
3. Go on a deck whose cue has no `cueSource` (loaded from a file saved mid-mix): the code is rewritten and evaluated, the name and file pointer stay. Test in Task 4.
4. Shift+double-click onto a stopped deck cues, and a plain double-click onto a stopped deck loads as today, so nothing changes for a user who never plays while browsing. Test in Task 6.
5. Cueing over a cue that has a sounding line lands on the bar, not at once: the old cued line keeps sounding until the flush. Test in Task 4.

- [ ] **Step 7: Implement `cueBlock` in `cue.ts`**

Walk `pattern.code.split('\n')` with `patternLines(pattern.code)` beside it. For each physical line: a blank line or a line whose trimmed text starts with `MARKER` is dropped; a line matching `/^\s*(setcpm|setcps)\(/` is dropped; the first physical line of a pattern line gets its label rewritten (`^(\s*)_?<label>:` → `_<slug>_<label>:`; `^(\s*)\$:` → `_<slug>_<n>:`; no label at all → `_<slug>_<n>: ` prefixed), where `n` counts unlabelled pattern lines from 1, except that a pattern with exactly one pattern line that is unlabelled gets `_<slug>:`; every other line (comments, continuations, other setup) is kept as it is. Prepend the marker: `` `${MARKER}${name} · ${cpm} cpm · its lines are on the home row · Go finishes, Clear drops` ``.

- [ ] **Step 3: Implement `goCode`, `clearCode`, `cueSounding` in `cue.ts`**

Both rewrites work on `code.split('\n')` with a set of physical line indices to drop and a map of indices to replace. `clearCode` drops the marker line and every cued line's `firstLine..lastLine`, plus any comment line directly above a cued line with no blank between (walk up while the line is a `//` comment), then trims trailing blank lines and collapses three or more consecutive newlines to two. `goCode` drops every own pattern line (a pattern line not in `cue.lines`) the same way with its attached comments, drops the marker, and rewrites each cued line's first physical line: a label of the form `<slug>_<rest>` where `rest` is not all digits → `<rest>:` (unmuted) or `_<rest>:` (muted); a bare slug or `<slug>_<digits>` → `$:` when unmuted, left as it is when muted. Same trailing-blank and newline collapse. `cueSounding` is `cue.lines.some((l) => !l.muted)`.
