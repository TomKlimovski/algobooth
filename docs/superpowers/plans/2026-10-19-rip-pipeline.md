# Rip Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rip tab that takes a YouTube URL and a start and stop time, runs a local Python analysis service, and hands back editable Strudel code plus the separated stems to audition against it.

**Architecture:** A Python 3.11 FastAPI service under `service/` runs the pipeline as independent modules (download, separate, grid, key, drums, bass, chords, sounds, generate, tidy) joined by plain pydantic data. The Rust shell launches the service with a random token, learns its random port from the service's first stdout line, supervises it, and hands port and token to the UI through one Tauri command. The Rip tab talks to the service over HTTP with a bearer token, auditions stems through Web Audio, runs the result in its own `StrudelMirror`, and loads or saves through the existing `DeckApi` and `LibraryStore`.

**Tech Stack:** Python 3.11 managed by `uv`, FastAPI + uvicorn, pydantic 2, `yt-dlp`, `ffmpeg` (system binary), librosa, numpy, scipy, soundfile, Basic Pitch on `onnxruntime`, PyTorch + Demucs (installed on first rip), `anthropic` SDK, pytest + `pytest-socket`. Rust: `std::process`, `rand`, `tauri::Emitter`. TypeScript: the existing Solid + vitest setup, `@strudel/codemirror` for the result editor.

**Spec:** `docs/superpowers/specs/2026-10-19-algobooth-design.md`, sections "Rip" (user experience), "Decided: the rip pipeline", "Settings" (the rip rows), and "Target machine, install size, and signing". This plan covers milestones 4 and 5. Milestones 1 to 3 are implemented from `docs/superpowers/plans/2026-10-19-booth-and-library.md`; this plan consumes their interfaces as they exist in the code today and re-plans none of them. Packaging the Python environment into the app bundle is milestone 6 and stays out of scope: here the service runs from `service/.venv`. One deliberate narrowing: the grid is fixed at 16 steps per bar; the spec's "finer resolution when onsets clearly fall off the 16 grid" is deferred until a real rip shows it is needed, since every builder in Task 10 takes `steps_per_bar` from the `Analysis` and can grow to 32 later.

## Global Constraints

- Python is exactly 3.11: `requires-python = ">=3.11,<3.12"` and `service/.python-version` is `3.11`. The environment is `service/.venv`, created and locked by `uv` (`uv sync` in `service/`). `uv.lock` is committed. Every dependency is pinned to an exact version in `pyproject.toml`.
- The service binds `127.0.0.1` only, on a port it picks (`port=0`), and refuses every request without `Authorization: Bearer <token>` with 401. The token is 32 hex characters generated by Rust per launch and passed in the environment variable `ALGOBOOTH_TOKEN`, never on the command line.
- One rip at a time: a second `POST /rip` while a job is queued or running returns 409. Demucs runs with `segment=5.0`, `shifts=0`, `overlap=0.1`, on `mps` when available, falling back to `cpu` on any MPS error, with `PYTORCH_ENABLE_MPS_FALLBACK=1` set. Stems are written to disk and dropped from memory as soon as they are written.
- Clip window: `0 <= start < end`, `end - start <= 60`. The UI parses `1:12` or `72` (or `1:02:03`) and the service validates the numbers (422 otherwise).
- PyTorch, torchaudio and Demucs, plus the `htdemucs` weights, are not in `service/.venv`: they install into the models folder on the first rip. Everything else, including Basic Pitch's own weights and `onnxruntime`, is in the venv. The models folder is Tauri's `app_data_dir()/models` (not user-settable); the rip cache folder is the `rip_cache_dir` setting (default `~/Algobooth/cache`).
- Tests never touch the network or download a model: `pytest` runs with `--disable-socket` (from `pytest-socket`) via `addopts`, every analysis test synthesises its audio in the test, and the real Demucs path is covered only by the manual verification steps. CI command: `cd service && uv run pytest`.
- Generated code must read like a person wrote it (spec anti-goal): `setcpm` first, one `$:` line per instrument group, mini-notation with `*`, `[]`, `<>` and Euclid where it fits, never a wall of numbers. The golden tests pin this.
- The Claude tidy pass is off by default, needs both a key and `tidy: true` in the request, and any failure in it leaves the rip successful with `tidied_code: null`.
- Licence AGPL-3.0; the product name is "Algobooth" and the word "strudel" never appears in the app name, bundle identifier, window title or the service's name (the package is `algorip`).
- Commit after every task with the attribution line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A clip in which kicks and hats land on the same step (four-on-the-floor with eighth-note hats) must come back as `bd*4` and `hh*8`, not lose the hats on the beats. Pinned in Task 6.
2. A stop time before the start, a window over 60 seconds, or a non-http URL must be refused by the UI before any request, and by the service with 422 if it arrives anyway. Pinned in Tasks 13 and 16.
3. The service dying mid-job (crash, or the user quitting Python) must leave the Rip tab showing "service stopped, restarting" and the job failed, never a spinner for ever. Pinned in Tasks 15 and 16.
4. The models download being interrupted (offline, or the app quit) must be resumable: the next rip offers the download again and a half-written `site` folder is never treated as installed. Pinned in Task 14.
5. Deck A holding unsaved edits when "Load to A" is pressed must ask first, exactly as a library load does, and never discard the edits. Pinned in Task 17.

Keys are `(bar, step)` on a 16-step grid.
  - `bass_line(notes: list[tuple[int, int, int, int]], bpm: float, bars: int) -> np.ndarray`: each `(bar, step, length_steps, midi)` is a sum of harmonics 1 to 6 with amplitude `1/n` (sawtooth-like), 10 ms attack and release.

  - `silence(seconds: float) -> np.ndarray`.
  - `mix(*parts: np.ndarray) -> np.ndarray`: zero-pads to the longest and sums, then scales so the peak is 0.9.
- Produces: `tests/conftest.py` fixtures `tmp_wav(tmp_path)` returning `write(name: str, y: np.ndarray) -> Path`, and `sr` returning `SR`.

### Task 2: Download and trim with cache

**Files:**
- Create: `service/algorip/download.py`, `service/tests/test_download.py`

**Interfaces:**
- Produces: `DownloadInfo` (pydantic): `path: Path`, `title: str`.
- Produces: `Fetcher = Callable[[str, Path], DownloadInfo]` (url, output directory). `yt_dlp_fetch(url, out_dir) -> DownloadInfo` is the real one: `yt_dlp.YoutubeDL({"format": "bestaudio/best", "noplaylist": True, "outtmpl": str(out_dir / "%(id)s.%(ext)s"), "quiet": True}).extract_info(url, download=True)`; `path` is `info["requested_downloads"][0]["filepath"]`, `title` is `info["title"]`.
- Produces: `Runner = Callable[[list[str]], None]` running a command and raising `RuntimeError(stderr)` on a non-zero exit; `run_command` is the real one (`subprocess.run(..., capture_output=True, check=False)`).
- Produces: `clip_key(url: str, start: float, end: float) -> str`: first 16 hex chars of sha256 of `f"{url.strip()}|{start:.3f}|{end:.3f}"`. `source_key(url) -> str` likewise over the url alone.
- Produces: `trim_command(source: Path, start: float, end: float, out: Path) -> list[str]`: `["ffmpeg", "-y", "-loglevel", "error", "-ss", f"{start:.3f}", "-to", f"{end:.3f}", "-i", str(source), "-ac", "2", "-ar", "44100", "-c:a", "pcm_s16le", str(out)]`.
- Produces: `fetch_clip(url, start, end, cache_dir: Path, keep_downloads: bool, fetch: Fetcher = yt_dlp_fetch, run: Runner = run_command) -> tuple[Path, str]` returning `(cache_dir/"clips"/f"{clip_key}.wav", title)`. The clip is cached: if the wav and its sidecar `<key>.json` (`{"title": ...}`) exist, nothing runs. The source download is cached under `cache_dir/"sources"/<source_key>/` with a sidecar `info.json` `{"path", "title"}`; when `keep_downloads` is false the source folder is deleted after trimming (but the clip stays).
- Produces: `probe_ffmpeg() -> str | None`: the `ffmpeg` path from `shutil.which`, or None.

### Task 3: Stem separation with a Demucs loader

**Files:**
- Create: `service/algorip/separate.py`, `service/tests/test_separate.py`

**Interfaces:**
- Produces: `STEMS = ("drums", "bass", "other", "vocals")`.
- Produces: `Separator = Callable[[np.ndarray, int], dict[str, np.ndarray]]`: takes a `(2, n)` float32 mix at `sr`, returns one `(2, n)` array per stem name in `STEMS`.
- Produces: `separate(clip: Path, out_dir: Path, separator: Separator) -> dict[str, Path]`: loads stereo, calls the separator, writes `out_dir/<stem>.wav` for each stem and `out_dir/mix.wav` (the clip resampled to 44100 stereo), returns the four stem paths plus `"mix"`. Cached: if all five files exist the separator is not called.
- Produces: `demucs_separator(models_dir: Path, device: str | None = None) -> Separator`: inserts `models_dir / "site"` at the front of `sys.path`, sets `TORCH_HOME` to `models_dir / "torch"`, imports `torch`, `demucs.pretrained.get_model("htdemucs")` once (module-level cache), picks `device` as `"mps"` if `torch.backends.mps.is_available()` else `"cpu"`, and returns a function that calls `demucs.apply.apply_model(model, mix[None], segment=5.0, shifts=0, overlap=0.1, device=device, progress=False)[0]` and maps `model.sources` to the arrays. On any exception while on `mps`, it retries the same call on `cpu` once and keeps `cpu` for the rest of the process.
- Produces: `DEMUCS_SEGMENT = 5.0` (the 8 GB RAM constraint).

### Task 4: Tempo, beats and bar grid

**Files:**
- Create: `service/algorip/grid.py`, `service/tests/test_grid.py`

**Interfaces:**
- Produces: `STEPS_PER_BAR = 16`, `BEATS_PER_BAR = 4`.
- Produces: `Grid` (pydantic): `bpm: float`, `first_downbeat: float` (seconds), `bars: int`, `steps_per_bar: int = 16`; properties `bar_seconds` (`240 / bpm`), `step_seconds`; methods `step_at(t: float) -> tuple[int, int] | None` (nearest step; None when before `first_downbeat` by more than half a step or past the last bar), `time_of(bar, step) -> float`, `end_time` (`first_downbeat + bars * bar_seconds`).
- Produces: `estimate_tempo(y: np.ndarray, sr: int) -> tuple[float, np.ndarray]`: `librosa.beat.beat_track(y=y, sr=sr, units="time")`; the tempo is `float(np.atleast_1d(tempo)[0])` folded into `[70, 180)` by doubling or halving (beat times are re-derived by interpolation when folded).
- Produces: `downbeat_phase(drums: np.ndarray, sr: int, beats: np.ndarray) -> int`: for each phase 0..3, sum the low-band (< 150 Hz, 4th-order Butterworth) RMS in a 60 ms window after each beat `beats[phase::4]`; return the argmax. With fewer than 4 beats return 0.
- Produces: `estimate_grid(mix: np.ndarray, drums: np.ndarray | None, sr: int, duration: float) -> Grid`: tempo from the mix, phase from the drums (the mix when drums is None), `first_downbeat = beats[phase]`, `bars = floor((duration - first_downbeat) / bar_seconds)`, bpm rounded to 1 decimal. Raises `ValueError("Could not find a beat")` when fewer than 2 beats are found or `bars < 1`.

### Task 5: Key estimation

**Files:**
- Create: `service/algorip/key.py`, `service/tests/test_key.py`

**Interfaces:**
- Produces: `PITCH_NAMES = ["C","C#","D","D#","E","F","F#","G","G#","A","A#","B"]` (sharps only, used everywhere a pitch class is named).
- Produces: `Key` (pydantic): `tonic: int` (pitch class 0..11), `mode: Literal["major", "minor"]`; `name` property (`"A minor"`); `scale` property, the set of 7 pitch classes (major: 0 2 4 5 7 9 11; minor: 0 2 3 5 7 8 10, each plus tonic mod 12).
- Produces: `MAJOR_PROFILE = [6.35, 2.23, 3.48, 2.33, 4.38, 4.09, 2.52, 5.19, 2.39, 3.66, 2.29, 2.88]`, `MINOR_PROFILE = [6.33, 2.68, 3.52, 5.38, 2.60, 3.53, 2.54, 4.75, 3.98, 2.69, 3.34, 3.17]` (Krumhansl-Schmuckler).
- Produces: `estimate_key(y: np.ndarray, sr: int) -> Key`: mean `librosa.feature.chroma_cqt` over the signal, Pearson correlation against the 24 rotated profiles, best wins; ties go to the lower tonic then major.
- Produces: `key_from_stems(other: np.ndarray, bass: np.ndarray, sr) -> Key`: `estimate_key` on `mix(other, bass)` (spec: "other" plus bass).

### Task 7: Bass transcription

**Files:**
- Create: `service/algorip/notes.py`, `service/algorip/bass.py`, `service/tests/test_bass.py`

**Interfaces:**
- Produces (`notes.py`): `Note` (pydantic): `bar: int`, `step: int`, `length: int` (steps, >= 1), `midi: int`. `NoteEvent = tuple[float, float, int, float]` = `(start_s, end_s, midi, amplitude)`.
- Produces (`notes.py`): `Predictor = Callable[[Path], list[NoteEvent]]`; `basic_pitch_predict(path: Path) -> list[NoteEvent]`: `basic_pitch.inference.predict(str(path))` returns `(model_output, midi_data, note_events)`; map each note event `(start, end, pitch, amplitude, bends)` to a `NoteEvent`.
- Produces (`notes.py`): `quantise(events: list[NoteEvent], grid: Grid, min_amplitude: float = 0.1) -> list[Note]`: start to nearest step, length `max(1, round((end - start) / grid.step_seconds))`, drops events under `min_amplitude` or outside the grid.

### Task 10: Mini-notation builders

**Files:**
- Create: `service/algorip/mini.py`, `service/tests/test_mini.py`

**Interfaces:**
- Produces: `bjorklund(k: int, n: int) -> list[bool]` (the standard Euclidean rhythm, first slot a hit).
- Produces: `euclid_match(steps: set[int], n: int = 16) -> tuple[int, int, int] | None`: `steps` are on an `n`-step bar. Tries `(k, m, rotation)` with `m = 8` first when `n == 16` and every step is even (the steps halved), then `m = n`, for `k` in `1..m-1` and rotation `0..m-1`, matching `bjorklund(k, m)` rotated right by `rotation`; the first match wins.
- Produces: `bar_mini(name: str, steps: set[int]) -> str` for one 16-step bar, first rule that applies wins:
  1. empty: `"~"`
  2. every `k`-th step from 0 with `16/k` in `{1, 2, 4, 8, 16}`: `f"{name}*{16 // k}"` (so `{0,4,8,12}` is `bd*4`, all 16 is `hh*16`, `{0}` is `bd`)
  3. the same but offset by half the period: `f"[~ {name}]*{16 // k}"` (so `{4,12}` is `[~ cp]*2`, `{2,6,10,14}` is `[~ oh]*4`)
  4. `euclid_match` with `k >= 2`: `f"{name}({k},{n})"` or `f"{name}({k},{n},{rotation})"`
  5. four beat groups of four slots joined by spaces: a group with no hits is `~`, otherwise `[x ~ x ~]` style with `name` or `~` per slot.
- Produces: `period(seq: list) -> int`: the smallest `p` dividing `len(seq)` with `seq[i] == seq[i % p]` for all `i`.
- Produces: `cycle(parts: list[str]) -> str`: the parts reduced to their `period`; one part is returned as is; more are `"<" + " ".join(parts) + ">"` where any part with a space outside brackets (a multi-group bar) is first wrapped in `[...]`, so each bar is one alternative.
- Produces: `voice_mini(name: str, bars: list[set[int]]) -> str` = `cycle([bar_mini(name, b) for b in bars])`.
- Produces: `note_name(midi: int) -> str`: `librosa.midi_to_note(midi, unicode=False).lower()` (`a1`, `c#2`).
- Produces: `notes_bar_mini(notes: list[Note]) -> str` for one bar: four beat groups of four slots; a note at slot `s` with length `L` (clipped to the end of its beat group) is `name` when `L == 1` else `name@L`, and occupies `L` slots; a group that is exactly one note filling all four slots is just `name`; a group with no notes is `~`; otherwise `[...]` of its items.
- Produces: `notes_mini(notes: list[Note], bars: int) -> str` = `cycle([notes_bar_mini(notes of bar b) for b in range(bars)])`.
